## 執行環境（已由 night_auto.bat 準備好）
- 目前資料夾是 git worktree `C:\hems-night`，分支是 `night-auto`（從 main 建立、並已快轉到最新的 main）。
  所有修改只在這個資料夾與分支進行；不要切換到 main、不要 merge、不要 push、不要動 `C:\hems`。
- 可用的工具：讀寫本資料夾內的檔案、`python -m pytest`、`git` 指令。其他工具（網路、安裝套件、PowerShell 等）都不可用。
- Python 與套件已在 PATH 中（專案虛擬環境），執行測試請用：`python -m pytest -q -p no:warnings`

## 任務：只做下一個未完成的一個項目，完成就停止
1. 讀 `CLAUDE.md`。依「製作順序」找下一個未完成的階段；其中：
   - 「階段 8 部署」需要作者登入雲端帳號、「階段 9」由作者自己製作，都不屬於自動任務，跳過。
   - 因此改看「介面改版待辦」：選第一個「未勾選」的批次，但跳過以下情況：
     標示（進行中）或（白天工作負責）的批次；標示「依賴第 N 批」而第 N 批尚未勾選的批次；需要網路的批次（夜間任務沒有網路）。
   - 若介面改版待辦全部完成，再依「優化方案」的順序做第一個未完成的項目。
   - 只做這一個項目，完成後不要開始下一個。
2. 照 `CLAUDE.md` 的「已確認的設計決策」實作，介面文字與註解用繁體中文，風格與現有程式一致。
3. 每改完一部分就執行 pytest；並確認程式能正常啟動：
   `tests/test_app.py` 用 Streamlit AppTest 實際執行 `app.py` 的各頁面，這組測試全部通過即代表程式能啟動。
   新增的頁面或功能也要補上對應的測試（包含 AppTest 頁面測試）。
4. 測試失敗就自己找原因修正。**不可以刪除、跳過（skip / xfail）或放寬既有測試的判斷條件。**

## 限制
- 不要修改 `core/` 資料夾內的演算法（模擬、負載、最佳化、指標的計算方式）。需要新資料可以在 `ui/` 或新模組處理。
- 不要新增清單以外的功能，不要大幅重構或改變檔案結構。
- 不要安裝新的套件。若這個項目一定需要新套件，請不要實作需要它的部分，在報告寫明需要哪個套件與原因。

## 停止規則
- 同一個錯誤嘗試修正 3 次仍失敗：用 `git restore .` 與 `git clean -fd` 還原這次的修改（先確認報告以外沒有要保留的檔案），
  然後寫報告說明原因並停止。
- 只有在「全部測試通過」時才 `git commit`，commit 訊息用中文說明做了什麼；失敗的半成品不要 commit。
- 測試全部通過後，更新 `CLAUDE.md` 對應項目的勾選（`- [ ]` 改為 `- [x]`），與程式一起 commit。

## 報告（無論成功或失敗，結束前都要寫）
寫入 `docs/night_report.md`（覆蓋舊內容），包含：
1. 做了哪個項目、改了哪些檔案（列出檔名與一句話說明）
2. 測試結果（通過／失敗數量，失敗的測試名稱）
3. 卡住的地方與原因（沒有就寫「無」）
4. 建議作者明天先檢查什麼、怎麼打開畫面驗證（例如：雙擊桌面 HEMS 圖示或在 `C:\hems-night` 執行
   `C:\hems\.venv\Scripts\python.exe -m streamlit run app.py`，到哪一頁、點什麼、應該看到什麼）
成功時報告跟著最後一次 commit 一起提交；失敗時報告留在資料夾中不要 commit。
