## 任務：依序做未完成的項目；做完一項且時間還夠，就接著做下一項
1. 讀 `CLAUDE.md`，找出「下一個可做的項目」：
   - 「製作順序」中的「階段 8 部署」需要作者登入雲端帳號、「階段 9」由作者與白天工作處理，都跳過。
   - 先看「介面改版待辦」，再看「優化方案」，依清單順序選第一個「未勾選」的項目，但跳過以下情況：
     標示（進行中）或（白天工作負責）的項目；標示「依賴 X」而 X 尚未勾選的項目；需要網路或安裝新套件的項目。
2. **時間規則**（開始時間與上限寫在本說明最上方）：
   - 每完成一項（全部測試通過、已 commit、已在 CLAUDE.md 勾選）後，執行 `date +%H:%M` 查看現在時間。
   - 若距離開始時間**未超過 60 分鐘**，接著做下一個可做的項目；超過 60 分鐘就停止並寫報告
     （留時間給下一項，避免做到一半被 90 分鐘上限強制結束）。
   - 任何一項失敗（依下方停止規則還原）就停止，不要再開始下一項。
   - 每一項各自 commit，不要把多項混在同一個 commit。
3. 照 `CLAUDE.md` 的「已確認的設計決策」實作，介面文字與註解用繁體中文，風格與現有程式一致。
4. 每改完一部分就執行 pytest；並確認程式能正常啟動：
   `tests/test_app.py` 用 Streamlit AppTest 實際執行 `app.py` 的各頁面，這組測試全部通過即代表程式能啟動。
   新增的頁面或功能也要補上對應的測試（包含 AppTest 頁面測試）。
5. 測試失敗就自己找原因修正。**不可以刪除、跳過（skip / xfail）或放寬既有測試的判斷條件。**

## 限制
- 不要修改 `core/` 資料夾內的演算法（模擬、負載、最佳化、指標的計算方式）。需要新資料可以在 `ui/` 或新模組處理。
- 不要新增清單以外的功能，不要大幅重構或改變檔案結構。
- 不要安裝新的套件。若這個項目一定需要新套件，請不要實作需要它的部分，在報告寫明需要哪個套件與原因。

## 停止規則
- 同一個錯誤嘗試修正 3 次仍失敗：用 `git restore .` 與 `git clean -fd` 還原這次的修改（先確認報告以外沒有要保留的檔案），
  然後寫報告說明原因並停止。
- 只有在「全部測試通過」時才 `git commit`，commit 訊息用中文說明做了什麼；失敗的半成品不要 commit。
- 測試全部通過後，更新 `CLAUDE.md` 對應項目的勾選（`- [ ]` 改為 `- [x]`），與程式一起 commit。

1. 做了哪些項目（依完成順序）、各自改了哪些檔案（列出檔名與一句話說明）、各項的 commit
